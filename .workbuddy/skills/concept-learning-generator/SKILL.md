# 概念学习资料生成器（Concept Learning Material Generator）

把一个抽象概念，变成一份"看得懂、用得上、可核查"的学习资料。

## 1. 适用场景

当用户出现以下意图时使用本 Skill：

- 明确说"我想学习 / 搞懂 / 理解 XXX"、"给我讲讲 XXX"；
- 要求"做一份 XXX 的学习笔记 / 学习资料 / 复习提纲 / 知识点总结"；
- 给出一个或多个新概念，希望得到结构化的解释材料；
- 需要把零散理解整理成可复用的知识卡片或网页。

适合：课前预习、课后复习、知识库沉淀、概念辨析与对比。

## 2. 输入信息

**必填：**

- `概念名称`：要学习的概念（可同时给多个，用顿号/逗号分隔）。

**可选（缺省时按默认值处理）：**

- `目标受众`（默认：非计算机专业的本科生）；
- `用户已有的理解`（用于校准难度和纠偏，有则必须认真对待）；
- `输出格式`（默认 HTML；也可 Markdown）；
- `侧重点`（如偏原理 / 偏应用 / 偏对比）。

## 3. 生成步骤

对每个概念，依次执行以下步骤，不要跳步：

1. **界定概念**：用一句话说清"它是什么"，并标注它所属的学科/领域。
2. **拆解机制**：列出它的核心组成或工作机理（3–5 点），善用生活类比帮助理解。
3. **找应用**：给出至少 1 个具体、可信的应用场景（能说清"谁、做什么、为什么用它"）。
4. **辨析边界**：找出最容易与之混淆的概念，并说明它的使用边界、局限或风险。
5. **设计自测**：给出 3–4 个能真正检验理解的自测问题，并附参考答案。
6. **找来源**：为关键论断附上可核查的官方文档、学术论文或权威资料链接。
7. **自查**：按第 6 节"自检要求"逐条核对后再交付。

若同时处理多个概念，额外生成一份"概念关系/对比说明"，说明它们之间的联系与区别。

## 4. 输出结构

每个概念输出一份独立文件，统一包含以下栏目（顺序建议一致）：

1. **学习目标**：3 条，可衡量（用"能解释/能说出/能举例/能区分"等动词）。
2. **核心问题**：2–3 个引导思考的问题，帮助读者带着问题读。
3. **个人解释**：用自己的话重述，**禁止整段照搬任何原文**。
4. **核心机制 / 组成**：结构化罗列，配类比或表格。
5. **应用场景**：至少 1 个具体例子。
6. **易混淆点 / 使用边界**：至少指出 1 个易混淆对象和 1 个边界/风险。
7. **自测问题**：含参考答案。
8. **可核查资料来源**：每条链接 + 一句话说明"它说明了什么"。

## 5. 资料来源要求

- **优先级**：官方文档（Anthropic、OpenAI、模型/框架官方）> 学术论文（arXiv 等）> 权威技术标准 > 高质量公开文章。
- **禁止伪造链接**：拿不准的链接必须先核实再写入；无法核实时，改用确知存在的官方首页/文档页，或干脆删去该条来源。
- **每条来源注明用途**：写清楚这条来源支撑了文中的哪个论断，便于读者核查。
- **区分事实与理解**："事实/定义"与"个人理解/个人判断"要分开标注，后者明确写"（个人理解）"。

## 6. 自检要求

交付前逐条确认，全部通过才算完成：

- [ ] 概念解释准确，无事实性错误，无明显编造；
- [ ] 第 4 节要求的 8 个栏目齐全；
- [ ] 应用场景具体，而非空泛套话；
- [ ] 至少指出一个易混淆点或使用边界；
- [ ] 自测问题与参考答案自洽、可判分；
- [ ] 来源链接真实、可点击、可核查，无伪造；
- [ ] 没有整段照搬某处原文（已用自己的话重述）；
- [ ] 格式统一、排版清晰、便于阅读。

## 7. 使用示例

**示例 1（单概念）**

> 用户："学习概念：大模型上下文窗口"
>
> → 按上述流程生成一份 `llm-context` 学习资料（默认 HTML）。

**示例 2（多概念 + 关系）**

> 用户："帮我学习 Agent 和 Skill 两个概念，并比较它们的关系"
>
> → 生成两份概念资料（`agent`、`skill`）+ 一份 `concept-relationship` 关系说明（含表格与 Mermaid 图）。

**示例 3（自定义侧重）**

> 用户："学习概念：正则化，侧重点：应用，输出 Markdown"
>
> → 生成偏应用视角、Markdown 格式的 `regularization` 学习资料。
