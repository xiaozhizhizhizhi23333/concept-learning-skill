2核心问题（带着问题读）

一个只会"回答问题"的大模型，凭什么被称为"智能体"？它到底多了哪一步？
如果 Agent 用到了一个错误的工具结果，它会怎样？这引出了什么关键设计？
Agent 的"自主性"一定是好事吗？

3个人解释

Agent（智能体）就是一个"能自己动手做事的 AI"。普通的大模型只会"想"和"说"——你问它，它回一段文字，仅此而已；而 Agent 会"想 → 做 → 看结果 → 再调整"，循环往复，直到把任务完成。

它的核心思路是：把大模型当作大脑，再给它装上"手脚"（工具）和"记事本"（记忆），让它能查资料、跑代码、读写文件、调用外部服务，并根据每一次行动的结果决定下一步。

打个比方（个人理解）：普通大模型像一位只能口述方案的顾问；Agent 则像一位能自己查资料、动手执行、遇到问题自己修正的实习生。

4核心机制 / 组成

组成作用类比
大脑（大模型 LLM）理解任务、推理、规划步骤、做决策人的大脑
工具（Tools / 函数调用）执行具体动作：搜索、跑代码、读写文件、调 API人的手和脚
记忆（Memory）短期靠"上下文窗口"，长期靠外部存储（如向量库）人的记事本
规划与循环（如 ReAct）在"思考下一步"与"执行并观察结果"之间循环边做边想的做事习惯
环境与反馈（Ground Truth）工具返回的真实结果，是纠错、判断进度的依据外界的真实反应

其中 ReAct（Reasoning + Acting）是一种经典范式：模型先"思考"该做什么，再"行动"调用工具，然后"观察"工具结果，据此继续。这个"思考—行动—观察"的闭环，正是 Agent 区别于普通对话模型的关键。

5一个具体应用场景

编程 Agent（自动修复 Bug）：你只说一句"帮我把这个报错修好"。它会：① 读代码定位问题；② 上网查这个报错的含义；③ 修改代码；④ 运行测试；⑤ 看测试结果——没通过就继续改，通过或遇到拦路时才来问你。Anthropic 官方文章提到，他们的编码 Agent 能自动完成涉及多个文件修改的任务（例如解决 SWE-bench 编程题）。

6易混淆点 / 使用边界

① Agent ≠ 聊天机器人：聊天机器人只输出文本，不调用工具、不改变外部状态；Agent 会"动手"。
② Agent ≠ 一定"完全自主"：Anthropic 把所有带工具调用的系统统称为"智能体类系统"，并进一步区分"工作流（流程由代码写死）"和"自主 Agent（由模型动态决定步骤）"。很多号称 Agent 的产品，其实只是工作流。
③ 边界与风险：自主性带来更高的 token 成本和"错误复利"——一步错可能步步错；还可能陷入无效循环、产生幻觉并基于幻觉行动。因此需要沙箱测试、护栏（guardrails）和最大步数等停止条件。
④ 能简单就别上 Agent：官方核心建议是"先用最简单的方案，必要时再增加复杂度"。不是所有任务都需要自主 Agent。

7自测问题

  1. Agent 与普通大模型最本质的区别是什么？
    答：Agent 会调用工具、采取行动，并根据环境反馈循环迭代；普通模型只生成文本。
  2. 为什么工具返回的"真实结果"对 Agent 很重要？
    答：它是 Agent 判断进度、发现错误、避免幻觉的"事实依据"（ground truth）。
  3. 请说出 Agent 的一个风险或边界。
    答：高 token 成本、错误复利、无效循环、基于幻觉行动等（答出一点即可）。
