大模型的上下文（Context）

1学习目标

  • 能解释"上下文窗口"是什么，并说明为什么大模型"没有长期记忆"。
  • 能说出上下文里通常包含的至少 3 类内容。
  • 能说明"上下文越长越好"为什么是错的，并举出一个相关现象或方法。

2核心问题（带着问题读）

模型"记得"你上一句话——它真的是"记住"了吗？
当你把一份很长的文档发给模型让它总结，它到底"看"到了什么？
上下文窗口塞得越满，效果一定越好吗？

3个人解释

大模型的"上下文"，可以理解为它一次性"看得见"的全部文字范围——就像一个只能容纳固定字数的"工作台"或"草稿纸"。

模型本身没有硬盘式的长期记忆：每次对话，它其实是把系统提示、你们的历史聊天、你贴进去的资料、以及它调用工具得到的结果，全部拼成一大段文字，一次性塞进这个工作台里再"读"。工作台装满了，最前面的内容就会被挤出去，模型就"看不见"了。这也是为什么长对话里模型会"忘记"开头说的话。

4核心机制 / 组成

要点说明
上下文窗口（Context Window）模型单次能处理的最大 token 数（不同模型可能是 128k、200k 甚至更多）。
Token（分词单位）不是"字数"。英文一个单词约 1 个 token，中文一个字约 1–2 个 token。
上下文的构成系统提示词 + 历史消息 + 上传/检索的资料 + 工具返回结果。
注意力与"位置"模型对不同位置的关注度不同，长文本里中段信息容易被"淹没"。
突破窗口的方法用检索（RAG）只把最相关的几段放进窗口，或对上下文做压缩/摘要。

5一个具体应用场景

RAG（检索增强生成）：当资料远超窗口时，不把所有内容都塞进上下文，而是先检索出最相关的片段，只把这几段放进上下文让模型回答。例如一个"问大学规章制度"的助手，背后有数万字的文件，它每次只把跟问题最相关的几条规则送进上下文——既省 token，又更准确、更少幻觉。

6易混淆点 / 使用边界

① "上下文" ≠ 模型的长期记忆：模型参数里存的不是"关于你"的记忆。所谓"记住"，只是这段对话还留在窗口里；一旦超出窗口，就会被"遗忘"。这也是为什么跨会话它通常不记得你。
② 上下文越长 ≠ 越好：有研究（"Lost in the Middle"）发现，信息放在长上下文中间时，模型反而容易"漏看"；同时长上下文更慢、更贵。
③ Token ≠ 字数：中英文换算不同，别把"10 万 token"误当成"10 万字"。
④ 边界与隐私：窗口满了会截断/遗忘旧内容；而敏感信息一旦进入上下文，就会被模型"读到"，因此要注意隐私保护。

7自测问题

  1. 为什么长对话里模型会"忘记"开头说的话？
    答：超出上下文窗口上限，最前面的旧内容被截断/挤出窗口。
  2. 上下文里通常包含哪几类内容？
    答：系统提示、历史消息、上传/检索的资料、工具返回结果等。
  3. "上下文越长越好"错在哪？
    答：存在"迷失在中间"现象（中段信息易被漏看），且成本更高、速度更慢。
